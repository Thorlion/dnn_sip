# CONV1 master programs

## Default RGB program

`single_master_imem.mem` is generated by
`new_sw/core_instruction/conv1_rgb21_program.py`. It streams 21 rows of
224 words for each of the three input planes. Input source address is
`0x10000 + channel*50176 + row*224` for zero-based rows and channels.
Input rows alternate between IB buffers 0 and 1.

DMA0 loads the 64 channel-0 slices into KSP buffer 0 before the first SCR.
During channels 0 and 1, it loads the next channel's slices into the
inactive buffer. Rows 4..18 leave room for four slices after the input
transfer. Rows 19 and 20 leave room for two slices each. This loads all
64 slices before the next channel starts. For output lane `k`, the source
is `0x35000 + k*363 + channel*121` and the destination is
`0x10000 + (channel % 2)*0x4000 + k*256`.

The first row of each channel is loaded before SCR. The following row
transfers use WAIT_ROW before reusing a consumed IB buffer. The last wait
of each channel consumes its row-21 event after the final OSP store.
The master uses slave entry PC 0 for channel 0 and PC 216 for channels 1
and 2. The final wait leads to the park loop.

The `conv1_rgb21` run passed with 63 input transfers, 192 weight transfers,
and all 14080 OSP results matching. Channel 1's weights were ready at
329.625 us and channel 2's at 584.995 us in the 10 ns clock simulation.

## Earlier channel-0 program

`conv1_channel0_master_imem.mem` contains 83 executable RV32/custom instruction words
(332 bytes), with assembly comments and byte-PC labels. Runtime loops cover
the first 41 image rows of channel 0 without unrolling every row.

1. Load the first channel of all 64 CONV1 kernels into KSP buffer 0.
2. NOP.
3. Load input row 1 into IB buffer 0; NOP delay; SCR starts the slave at PC 0.
4. Load input row 2 into IB buffer 1; DMA delay; WAIT_ROW consumes row 1's event.
5. Reuse IB buffer 0 for row 3; DMA delay; WAIT_ROW consumes row 2's event.
6. After loading each input row from 4 through 19, prefetch four channel-1
   kernels into KSP buffer 1. Then wait for the previous row's event.
7. Continue the ordinary input loop for rows 20 through 41.
8. WAIT_ROW consumes row 41's event, then park with `jal x0, park`.

SCR is encoded as `0000000B` (opcode `0x0B`, rs1=x0) at master byte PC
`0x80`. It follows the first row's DMA wait. x10 retains the initial row
count; subsequent rows branch around SCR as x9 decreases. The slave starts
once and continues while the master streams later rows. Row 1 jumps around
WAIT_ROW so the master can prefetch row 2 while the slave computes row 1.
After loading each row `n=2..41`, WAIT_ROW consumes row `n-1`'s completion
before row `n+1` can overwrite that row's old buffer.

WAIT_ROW uses the word `0000002B` at byte PC `0x88` in the ordinary loop,
`0xC8` at entry to the prefetch loop, and `0x134` after each prefetch batch.
The final wait at
`0x9C` consumes row 41's event; the park instruction is at `0xA0`.
The slave program must emit one ROW_DONE event per consumed input row in
order, using bit 37 after each row's loop. Missing events leave the master
stalled. The event has no row number or buffer ID, and only one pending
event is remembered. The matching 279-word slave program covers all 41 input
rows and supplies these markers. It computes channel-0 contributions for
nine complete output rows, occupying OSP addresses 0..494 in each lane.

KSP buffer 0 holds channel 0 for the active slave program. KSP buffer 1
receives channel 1, with one 121-word kernel slice per output lane.

## Addressing

All DMA addresses and sizes count 16-bit words. With the existing contiguous
OIHW parameter layout, each output kernel has `3*11*11 = 363` words.
For kernel `k=0..63`, the program transfers 121 words:

```text
OM source       = 0x35000 + k*363
KSP destination = 0x10000 + k*256  (buffer 0, lane k, word 0)
```

Each kernel is a separate DMA0 transfer, accounting for the channel stride
in OM and the 256-word lane stride at the destination. For input row
`y=0..40`, it transfers 224 words:

```text
OM source      = 0x10000 + y*224
IB destination = 0x00000 if y is even, 0x00400 if y is odd
```

Every row starts at local IB word 0. Row 41 reads
`0x12300..0x123DF` into buffer 0. Streaming overwrites each buffer when it is
reused; WAIT_ROW requires the old row's completion before that reuse.

## Channel-1 weight prefetch

The entry guard runs after row 3's DMA delay, when x9 equals 39. It prepares
the prefetch pointers before consuming the row-2 event. The first batch
starts after the row-4 input transfer, whose last write is at 186.885 us
with the current 10 ns clock. Each batch loads lanes
`4*(n-4)..4*(n-4)+3` after input row `n=4..19`.

```text
OM source       = 0x35079 + k*363
KSP destination = 0x14000 + k*256  (buffer 1, lane k, word 0)
```

Four slices require 484 payload cycles, or 4.84 us at the testbench clock.
Rows 4..19 are loaded while the slave is processing at least two vertical
passes of the previous input row, leaving a longer gap than the 3.81 us
single-pass case. The batch completes before the slave begins the
prefetched input row. The slave continues to read KSP buffer 0.

## DMA commands and delays

DMA_CONFIG uses opcode `0x78`, funct3=0 (DMA0), rd=0 and forwarded rs1 data.
The immediate selects the CSR: source=0, destination=4, size=8, START=12.
Writing START=1 launches the configured transfer. Registers are:

| Register | Use |
| --- | --- |
| x5 | OM source pointer |
| x6 | KSP lane pointer / IB buffer address |
| x7 | Transfer size (121 kernel words or 224 row words) |
| x8 | Constant 1 for START |
| x9 | Remaining kernels / rows |
| x10 | Initial row count, used to execute SCR only after row 1 |
| x11 | NOP-delay loop counter |
| x12 | Row-3 entry check, then channel-1 weight source |
| x13 | KSP buffer-1 lane destination |
| x14 | Channel-1 kernel size (121 words) |
| x15 | Remaining four-kernel batches |
| x16 | Remaining kernels in the current batch |

Each transfer is followed by a delay loop containing NOP, ADDI and BNE.
Startup kernel delays use 42 iterations and ordinary row delays use 76.
The prefetch loop uses 38 iterations after each input transfer and 21 after
each weight transfer. These tighter delays rely on the current master's
taken-branch and dependency stall cycles. WAIT_ROW waits for the slave's
consumption event.

ROW_DONE does not pause the slave. The next row must finish loading before
the slave begins reading it. This schedule prefetches one row ahead, but
does not provide a separate slave-side DMA-ready handshake.

The schedule issues 169 DMA0 transfers containing 24672 payload words
(`2*64*121 + 41*224`), plus one SCR and 41 WAIT_ROW consumptions.
The testbench run window is 100000 cycles so it can accommodate these loads
and the delay-loop overhead. Its FINISHED marker is not a functional check.

The `conv1_channel0` checker validates all 16 prefetch batches, the contents
of KSP buffer 1, and the 31680 channel-0 OSP results.
