# CONV1 slave programs

## Default RGB program

`single_slave_imem.mem` contains 432 instructions generated by
`new_sw/core_instruction/conv1_rgb21_program.py`. The program processes
input rows 1..21 for all three channels. Per lane, OSP address
`55*oy + ox` holds the three-channel Q8.8 dot product for
`oy=0..3`, `ox=0..54`. The four complete output rows use 220 words per lane.
The results are sums of products before bias or activation.

Entry PC 0 initializes each output when channel 0 first contributes to it.
Entry PC 216 reads existing OSP sums for channels 1 and 2 and switches to
the prefetched KSP buffer. The first instruction of that entry accounts
for the retained KSP and OSP counters from the preceding channel.

Contexts 1 and 2 handle taps and interior windows. Context 3 repeats the
four-row stripe. Context 4 repeats rows 5..6, 15..17, and 19..20 with
relative address updates. Every issued instruction does a MAC on all 64
lanes. Each channel consumes 25284 MAC cycles and emits 21 ROW_DONE events.
The last store of each channel also asserts DONE, allowing the master
to load the next plane's first row before its SCR.

Run `python new_hw/script/run.py test=conv1_rgb21` from `source`.
The Verilator test passed with all 14080 RGB dot products matching.

## Earlier channel-0 program

`conv1_channel0_slave_imem.mem` is exported from
`new_sw/core_instruction/single_temp.xlsx`, worksheet `Sheet1`.
It contains 279 instructions at PC 0..278 and operates from reset state.
The workbook's `Sheet2` is preserved as a separate reference; it is not exported.

The workload uses a 224x224 input plane, an 11x11 kernel, stride 4 and padding 2.
Each of the 64 lanes uses the first input channel of its own output kernel.
Input rows 1..41 produce nine complete output rows, with 55 columns each.
Only channel-0 partial sums are calculated; channels 1/2, bias, activation,
and the OSP-to-OB path are outside this program.

For lane `k`, OSP address `55*oy + ox` holds the signed Q8.8 sum for
`oy=0..8`, `ox=0..54`. Addresses 0..494 are used; 495..511 are untouched.
Each product truncates eight fractional bits, and accumulation wraps at 16 bits.

## Input-row transactions

One transaction consumes one input row from an IB buffer. That row updates
every selected output row whose vertical kernel overlaps it, up to three
output rows per transaction. For input row `y` and output row `oy`,
`ky = y - 4*oy + 2`; the pass is included when `0 <= ky <= 10`.

IB switches once at the beginning of each new input-row transaction after
row 1. The first row uses buffer 0; even-numbered rows use buffer 1 and
odd-numbered rows use buffer 0. Every vertical pass clears IB to address 0
without switching buffers again. KSP remains in buffer 0.
ROW_DONE is set only on the last store of the last pass for that input row.
The master prefetches the next row and consumes this event before buffer reuse.

| Slave PC | Work |
| --- | --- |
| 0..89 | Input rows 1..6, including initialization of the first two output rows |
| 90..188 | Four-row stripe body repeated seven times, covering input rows 7..34 |
| 189..278 | Input rows 35..41, completing the last output rows |

Loop context 1 repeats taps within a horizontal window. Context 2 repeats
the 53 interior output columns. Context 3 stores PC 90 with count 6 at PC 89;
PC 188 conditionally branches to it, so the stripe body executes seven times.
Relative OSP addresses advance its output rows by one on each repetition.

Each horizontal pass performs nine real MACs at the left edge, eleven for
each of 53 interior positions, and ten at the right edge (input columns
214..223). Zero-padding products are omitted. This is 602 MACs per vertical
pass, 97 passes, or 58394 MACs per lane. The final instruction at PC 278
stores the last partial sum and sets both ROW_DONE and DONE. Completion
asserts after the pipeline's final store drains.

## Export and simulation

From `source`:

```powershell
python new_sw/core_instruction/core_compiler.py --input new_sw/core_instruction/single_temp.xlsx --output new_hw/tb/single_system/slave_mem/conv1_channel0_slave_imem.mem
python new_sw/core_instruction/conv1_channel0_reference.py
python new_hw/script/run.py test=conv1_channel0
```

Regenerate the reference after changing the input image or weights. Its
31680 words are lane-major: `reference[lane*495 + osp_address]`.
The checker compares every selected OSP word, checks row-event/wait and DMA
counts, rejects active-IB overwrite conflicts and out-of-range accesses,
and requires the master to reach its park loop.

The checker also verifies all 7744 channel-1 weights in KSP buffer 1 and
checks that each batch fits between the input DMA completion and the next
slave row's start. Logs are in `DSIP/tmp/verilator/conv1_channel0/`.
